# Android 智能晨间闹钟设计规格

## 1. 产品目标

构建一款采用 Apple 式克制视觉语言的 Android 闹钟应用。应用以可靠唤醒为第一优先级，在常规铃声之外，可按用户配置自动播报天气、内置新闻源和自定义 RSS 内容。

首个版本是面向 Android 10 及以上设备的可安装 MVP，不包含 iOS、账号体系、云同步、商业新闻 API 或应用商店运营后台。

## 2. 核心体验

应用采用随系统或时间自动切换的明暗主题。白天使用浅色卡片与柔和层次，夜间使用近黑背景、超大时间数字和橙色强调。界面保持低信息噪声、大圆角、清晰层级和自然动效。

底部导航包含四个入口：

- **闹钟**：显示下一次响铃、闹钟列表、启停状态和快速新增入口。
- **日历**：公历与农历同屏，展示二十四节气、中国法定节假日和调休信息，并支持按日期记录纯文字备注。
- **资讯**：管理内置推荐新闻源、自定义 RSS、订阅状态和内容预览。
- **设置**：管理定位城市、语音、语速、主题、通知、精确闹钟权限及数据更新时间。

## 3. 闹钟创建与日期规则

创建或编辑闹钟时依次配置：

1. 时间、名称和启用状态。
2. 日期规则：每天、法定工作日、周末、自定义星期、公历日期、农历日期或二十四节气。
3. 节假日策略：照常响铃、节假日跳过、仅法定工作日响铃。
4. 唤醒内容：常规铃声、天气、新闻和指定 RSS 订阅。
5. 播报顺序：用户可拖拽调整天气、新闻和各 RSS 源的先后顺序。
6. 播报参数：新闻条数、语速、音量，以及是否先播报日期和时间。

农历规则支持按月或按年重复。遇到闰月和普通月同名时，默认仅在普通月份触发。二十四节气可作为年度重复触发规则。

中国法定节假日与补班日按年份更新并缓存。“法定工作日”必须识别周末补班，不能简单等价于周一至周五。

## 4. 日期备注

用户可在日历中选择任意公历日期并新增、编辑或删除纯文字备注。存在备注的日期显示低干扰圆点标识，日期详情页显示完整备注。

MVP 中备注不产生独立通知，也不加入晨间语音播报。备注随本地数据库持久化。

## 5. 响铃与播报流程

Android 使用系统精确闹钟能力调度下一次触发。到点后显示锁屏可见的全屏闹钟界面，并按以下流程执行：

1. 铃声从较低音量渐强播放。
2. 用户可选择停止或稍后提醒。
3. 用户停止铃声后，应用根据闹钟配置自动开始晨间播报。
4. 播报先读取已准备的数据；必要时在短超时内刷新天气和资讯。
5. 播报结束后返回闹钟列表，并计算、注册下一次触发时间。

应用在设备重启、系统时区变更、日期变更及应用升级后重新计算并注册有效闹钟。若精确闹钟、通知或后台相关权限不可用，应用在闹钟列表和设置页明确显示风险与修复入口。

## 6. 天气、新闻与 RSS

天气支持自动定位和手动指定城市。拒绝定位时引导用户选择城市，不阻断闹钟创建。天气播报至少包含当前天气、温度区间、降水提醒和简短出行建议。

新闻同时支持：

- 应用内置的推荐 RSS 新闻源。
- 用户添加的自定义 RSS/Atom URL。

添加订阅时需要校验 URL、解析 Feed 元数据并提供内容预览。RSS 内容进入播报前移除 HTML、脚本和无意义空白，单条默认朗读标题及有限长度摘要。解析异常、超时或单个订阅不可用时跳过该来源，不影响闹钟和其他播报内容。

## 7. 离线与错误处理

可靠响铃不依赖网络。网络数据采用以下降级策略：

- 天气刷新失败时使用最近一次有效缓存，并在播报中说明数据时间；没有缓存则跳过天气。
- 新闻或 RSS 刷新失败时使用仍在有效期内的缓存；没有可用内容则跳过该来源。
- 节假日数据更新失败时继续使用已缓存年份；缺少目标年份时提示用户，且不把普通周一至周五冒充法定工作日。
- TTS 引擎不可用时保留铃声功能，并在应用内提供系统语音引擎设置入口。
- 任一内容模块失败都不得阻塞闹钟响铃、停止和稍后提醒。

## 8. 技术架构

采用 React Native 与 Expo Development Build。通用界面、状态管理和业务逻辑使用 TypeScript；精确闹钟、全屏通知、开机恢复和必要的音频生命周期能力通过 Android 原生模块实现。

模块边界如下：

- `alarm-domain`：闹钟实体、重复规则和下一次触发计算。
- `alarm-scheduler`：Android 精确闹钟注册、取消与恢复。
- `calendar-domain`：公历、农历、闰月和二十四节气转换。
- `holiday-service`：法定节假日与调休数据获取、验证和缓存。
- `weather-service`：定位、城市选择、天气读取和缓存。
- `feed-service`：RSS/Atom 校验、解析、清洗、预览和缓存。
- `speech-service`：播报队列、TTS 参数和中断控制。
- `audio-service`：铃声、渐强音量和音频焦点。
- `storage`：闹钟、订阅、日期备注、设置和缓存元数据。

各内容模块通过结构化播报项输出给 `speech-service`。调度模块只依赖计算后的触发时间，不直接依赖天气、RSS 或 TTS。

## 9. 数据与隐私

MVP 数据默认保存在设备本地，不要求登录。定位仅用于获取本地天气；手动城市模式下无需持续定位。自定义 RSS URL、日期备注和闹钟配置不上传到自有服务器。

应用首次使用相关能力时按需申请通知、精确闹钟、全屏提醒和定位权限，并说明权限用途。权限拒绝不导致崩溃，且设置页持续展示能力状态。

## 10. 测试与验收

自动化测试覆盖：

- 每日、星期、公历、农历、节气和法定工作日规则的下一次触发计算。
- 农历跨年、大小月和闰月；同名闰月仅普通月份触发。
- 节假日、周末补班和跨年数据边界。
- 时区变化、系统时间变化和设备重启后的重新调度。
- RSS、Atom、异常 XML、HTML 清洗、超时和缓存降级。
- 天气定位拒绝、手动城市、离线和缓存过期。
- 日期备注的新增、编辑、删除与持久化。
- 播报队列排序、跳过失败项、暂停与停止。

真机验收至少覆盖一个主流 Android 版本和一个受后台限制较强的厂商系统。验收标准是：已获得必要权限时，应用被划走或设备重启后，闹钟仍能在计划时间的一分钟内可靠触发；网络内容失败时，铃声、停止与稍后提醒仍完全可用。

## 11. MVP 边界

首版包含 Android 应用、精确闹钟、全屏响铃、自动播报、公农历和节气规则、法定节假日与调休、日期文字备注、天气、推荐新闻源、自定义 RSS、本地存储和明暗主题。

首版不包含 iOS、登录、云同步、备注提醒、备注语音播报、跨设备同步、商业新闻 API、复杂推荐算法或服务端内容聚合。
